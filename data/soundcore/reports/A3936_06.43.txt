- The state reply is the same as in the first session, apart from the masked serial.
- 03 87 body, 92 bytes, as OpenSCQ30 builds it: preset number (2 bytes, little-endian; FE FE
  for a custom curve), favourite music genre (2), 10 bands for each earbud (20; one byte per
  band, 0x78 = 0 dB, 0.1 dB per step: B4 = +6 dB, 3C = -6 dB), gender, age range and an unknown
  byte (3), HearID curve (20), HearID time (4), HearID type (1), custom HearID curve (20), then
  the 10 bands again after OpenSCQ30's apply_drc() (20): the +6 dB on the lowest band comes out
  as 80 74 79 there.
- A preset write (22:07:19, preset 0) sends 9 bands of 78 and a 00 for each earbud.
- 05 01 read all zero this time: 05 81 clears the statistics 05 01 reads.
- 3D sound is not in OpenSCQ30's A40 module. Which state byte holds it is not known yet: the
  state was read only while it was off.
