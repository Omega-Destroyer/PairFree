# Cambridge Audio (local draft)

This branch adds **Melomania 1+ and Melomania Touch** from Melomania 2.8.12's local Bluetooth code.
Neither has been tried with PairFree. Close Melomania before connecting through the paired-device list.
The shared GAIA service alone never identifies an unknown headset as Cambridge Audio.

- Home shows each earbud's battery; Touch also has ambient sound and its level.
- Sound offers six presets and five numbered gain sliders from -6 to +6 dB. Choose a preset before
  editing a custom curve whose values PairFree has not set. Edits use the earbuds' custom EQ mode. The source does not
  supply numeric band frequencies, so these controls do not draw a curve or import frequency-based profiles.
- Controls enables or disables each built-in function, preserving unrelated bits of the device's mask.
- Device offers the eight built-in voice languages and SBC/AAC/aptX preferences when both earbuds are
  available. A preference changes what codecs the earbuds advertise. It does not force Android's codec.
- Device reports keep requested settings replies, redact the two addresses and discard unknown extensions.

The original Melomania 1 and the newer Melomania Connect models (A100, M100, P100) are outside this draft.
Firmware installation is excluded, including the high-performance/low-power audio switch: the vendor
implements that switch by installing a different bundled firmware image. No firmware, factory reset,
account or location traffic is sent. The vendor's phone-local custom slots are not imported.

## Tested virtually

Melomania 1+ and Touch have been connected to the **official vendor app** as virtual Bluetooth devices.
This checks the app's outgoing command encoding against synthetic device replies. It is a separate
category from testing PairFree on real earbuds; neither model counts as hardware tested.
The [virtual-test record](../cambridge/VIRTUAL_TESTING.md) lists exactly which settings were exercised.

Review the [protocol and implementation notes](../cambridge/PROTOCOL.md) before merging this draft.
All vectors are analytical and replies in tests are synthetic; no hardware success is claimed.
