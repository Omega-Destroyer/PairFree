# Huawei implementation and validation

The same HuaweiTalk runs on Android and Windows through BrandSpec, TalkDriver and Conversation. The operating system resolves the Bluetooth Classic SPP service. The shared Gradle task generates the product and command tables from [data/huawei](../../data/huawei).

- Exact model and alias detection keeps general SPP accessories and unrelated Huawei products out. Each bundled AI Life audio model has a connection profile. [Model audit](MODELS.md) · [Generated device table](../devices/huawei.md)
- A setting becomes writable after a valid model-specific reply. FreeBuds 3 uses scalar ANC. FreeLace Pro uses the legacy or modern write layout according to the state read it answers. Android's noise picker and the desktop tray offer the modes the model supports.
- The Sound tab selects built-in presets and the custom slots reported by the device. Nine profiles can write a ten-band curve when a slot is free or the PairFree slot is present. PairFree's local profile library holds saved curves. Studio's preset-only write path unlocks after a battery reply because the reference profile does not query EQ.
- Reports include the canonical model, firmware version and acknowledged command IDs. They exclude command payloads, Bluetooth names, addresses, serials and custom EQ names.

Android's dev APK built and the Windows UI and transport sources compiled. The Kotlin suite covers stream recovery, ANC variants, Walrus gesture masks, Eyewear battery, language, both generations' gestures and switches, pinch slots Studio touch-lock framing and EQ slot preservation. The Pro 3 EQ test uses a published LibreBuds vector. The supplied APK follow-up added both generations' settings exposed over MBB and checked the FreeGO, Walrus, Roc, Mermaid and Nile screen routes. PairFree has yet to be tested on physical Huawei hardware. The earlier AI Life emulator session reached setup without MBB traffic.
