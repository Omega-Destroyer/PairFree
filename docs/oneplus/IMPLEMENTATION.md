# OnePlus / OPPO local protocol-core draft

Branch `brand/oneplus` adds OPOv1 encoding and bounded stream/fragment decoding, inner command/sequence
matching keys, three narrow read builders, capability bit decoding and raw-type battery records.
Constants come from `data/oneplus/commands.json`, generated by `generateOneplusTables`.
The source is HeyMelody 117.6.6, particularly F8/b, G8/b and PollCommandManager, as documented in
[PROTOCOL.md](PROTOCOL.md). No vendor or AGPL code was copied. No socket, model or setting is enabled.

The 4096-byte logical-packet limit is a local settings-traffic bound, not a vendor MTU. The decoder
separates MTU chunks from numbered logical fragments, rejects orphan/out-of-order fragments, validates
inner declared lengths, and resets a fragment chain after malformed data or a fresh whole frame.
Two-byte length varints cover this bound; noncanonical or longer varints are rejected. Reserved bytes
are skipped as the vendor reader does. Fragment numbers follow F8/b's zero-based byte counter.

Only capability, product and battery read helpers exist. Debug, upgrade, identity/account-key and
arbitrary feature probes are not part of startup code. Raw battery types are deliberately not assigned
left/right/case names until their vendor enum mapping is implemented. Capability bits still need the
per-model feature predicates in MODELS.md before they can authorize UI settings.

Remaining implementation: import selected factual model fields into a public schema, finish per-model
setting enums/units, apply product-id remappings, map battery component types, negotiate transport/MTU,
add sequence-aware session queues, settings/EQ/controls, identification, reports and device pages.
These are unfinished tasks, not protocol blockers. All model catalog records remain research leads.

Tests use the analytical capability-read vector, synthetic two-byte lengths, fragmented/coalesced
streams, reordered/missing fragments, malformed lengths, reset, sequence keys, error status, packed
battery levels and LSB-first capability bits. No hardware success is claimed.
